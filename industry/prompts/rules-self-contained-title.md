
【标题自洽规则 — 让读者不点开就知道"这是关于谁的什么事"】

1. 标题必须点出核心主体：公司名 / 产品名 / 岗位或团队名 / 机构名 / 项目名。
2. 原标题已经清楚点出主体的：英文标题翻译成中文、中文标题保持原意，不要为改写而改写。
3. 原标题只是版本号 / 代号 / 没信息量的 teaser（如 "v2.1.159"、"Small is a feature"、"Day 1"、"重磅发布"）时，结合【来源】和正文把主体补进标题。例：原标题 "v2.1.159" + 来源 "Workday Release Notes" → "Workday 发布 v2.1.159 更新"。
4. 补主体只能用【来源】或正文里真实出现的名字。正文和来源都没点出具体产品、团队或岗位时，用上位词（如"某 HR SaaS 厂商"、"某 FDE 团队"）兜底，绝不凭"行业常识"编一个具体公司、产品、岗位、人数或数字。
5. 原标题表达的【文章类型和核心动作】是硬边界：How / Why / Guide / Analysis / Review / Benchmark 这类解释、分析、教程或评测标题，中文标题必须保留这个类型；不能因为正文谈到一个已经存在的产品、岗位或新数据，就改写成“发布 / 推出 / 上线 / 开源”或“招聘 / 裁员”。只有原标题明确宣布了发布、推出、上线、招聘或裁员，中文标题才能使用对应动作。保留文章类型不等于删主体：仍须按第 1-4 条补全正文或来源明确给出的公司、产品、团队名。
   例：原标题 "How Workday is redesigning the performance review" → "Workday 如何重做绩效评估"，不能写成 "Workday 发布新的绩效产品"。
   例：原标题 "How to build a forward deployed engineering team" + 来源和正文明确是 Palantir → "Palantir 如何搭建 FDE 团队"，不能只写成缺主体的 "如何搭建 FDE 团队"。
6. 本条的动作和背景里的旧发布要分清：原文把发布写成过去的事（“Last week we launched …”“上周我们发布了…”），本条是在讲用法、做演示或再次推广时，标题写介绍、演示或讲解，把发布交代成此前的事；不能写成“推出 / 发布 / 上线”，否则读者会当成今天的新闻。只有原文明确某项能力是现在才开放或新增，才对那一项用对应动作。
   例：正文 "Last month we launched the new payroll module. Here is how it works." → "HiBob 介绍上月上线的薪酬模块用法"，不能写成 "HiBob 推出薪酬模块"。
